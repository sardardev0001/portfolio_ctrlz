# گزارش تغییر محدودیت آپلود ویدیو CTRL.Z

تاریخ: ۲۷ اکتبر ۲۰۲۶

## ۱. محدودیت قبلی و جدید

| مورد | قبلی | جدید |
| --- | --- | --- |
| حجم هر فایل ویدیو | ۲۰۰٬۰۰۰٬۰۰۰ بایت | ۱٬۰۷۳٬۷۴۱٬۸۲۴ بایت، دقیقاً ۱ GiB |
| حداقل مدت | ۳۰ ثانیه | حذف شده؛ صفر در بررسی عددی مجاز است، اما فایل باید فریم ویدیویی قابل رمزگشایی داشته باشد |

محدودیت حجم و مدت برای هر فایل است. هیچ سقف مجموعی برای ویدیوهای یک پروژه اضافه نشده است. مدل فعلی پروژه و ارتباط آن با فایل رسانه تغییر نکرده‌اند. محدودیت ۱۰٬۰۰۰٬۰۰۰ بایتی تصاویر و اسناد حفظ شده است.

## ۳. فرانت‌اند، بک‌اند و ذخیره‌سازی

فرم ساخت و فرم ویرایش پروژه از کامپوننت مشترک `VideoUpload` استفاده می‌کنند. فایل قبل از شروع ارسال از نظر حجم، قالب، مدت و وجود ابعاد ویدیویی در مرورگر بررسی می‌شود. حجم به بایت و مدت به ثانیه نمایش داده می‌شود. رسیدن پیشرفت به ۱۰۰٪ با پیام بررسی و ذخیره در سرور همراه است؛ موفقیت نهایی فقط پس از پاسخ بک‌اند نمایش داده می‌شود.

متن فارسی راهنما:

> می‌توانید برای هر ویدیو تا ۱ گیگابایت فایل آپلود کنید. مدت‌زمان ویدیو باید حداکثر ۲ دقیقه باشد.

بک‌اند مستقل از متادیتای ارسالی کلاینت، حجم را هنگام دریافت قطعات کنترل می‌کند. FFprobe قالب، کدک، جریان ویدیویی، ابعاد و مدت فایل واقعی را می‌خواند. سپس FFmpeg جریان ویدیو و صدای موجود را با توقف بر خطای رمزگشایی بررسی می‌کند. نبود فریم قابل رمزگشایی، فایل صوتی بدون ویدیو، خرابی و قالب/کدک ناسازگار رد می‌شوند. زمان خروجی رمزگشایی هم بررسی می‌شود تا مدت کمترِ اعلام‌شده در ظرف فایل، سقف ۱۲۰ ثانیه را دور نزند. رمزگشایی حداکثر تا ۱۲۱ ثانیه ادامه می‌یابد؛ فایل‌های مجاز به‌طور کامل بررسی می‌شوند. مهلت FFprobe برابر ۴۵ و مهلت رمزگشایی برابر ۶۰۰ ثانیه است. نبود ابزار یا پایان مهلت با خطای سرویس پاسخ داده می‌شود و فایل به‌عنوان معتبر ذخیره نمی‌شود.

پشتیبانی کدک قبلی حفظ شده است: MP4 با H.264/yuv420p و صدای AAC؛ WebM با VP8/VP9 و صدای Opus/Vorbis. هیچ کدک تازه‌ای اضافه نشده است.

پراکسی قبلی قطعات کل درخواست را در آرایه نگه می‌داشت و با `Buffer.concat` یکجا ارسال می‌کرد. مسیر جدید با backpressure روی دیسک می‌نویسد، حجم واقعی را اندازه می‌گیرد و سپس فایل را جریانی به بک‌اند می‌فرستد. این روش برای درخواست‌های بدون Content-Length نیز طول معتبر برای WSGI فراهم می‌کند. فایل‌های موقت پس از پایان، تخطی یا قطع ارسال پاک می‌شوند. فایل‌های بزرگ در Django از قبل روی دیسک دریافت می‌شدند؛ اعتبارسنجی اکنون همان فایل را استفاده می‌کند و کپی یک‌گیگابایتی دیگری نمی‌سازد.

ذخیره‌سازی S3/MinIO همچنان از مسیر و نام UUID قبلی استفاده می‌کند. انتقال multipart از طریق SDK انجام می‌شود. آستانهٔ ۵ MiB برای فایل موقت S3 از نگه‌داشتن کل فایل بزرگ هنگام بازخوانی آن در حافظه نیز جلوگیری می‌کند. احراز هویت مدیریتی، CSRF و دسترسی خصوصی فایل‌های منتشرنشده حفظ شده‌اند.

برای هر آپلود هم‌زمان نزدیک سقف، حدود ۲ GiB فضای موقت آزاد بین فرانت‌اند و بک‌اند لازم است؛ فضای ذخیره‌سازی نهایی و فایل‌های موقت بازخوانی رسانه جداگانه محاسبه می‌شوند. محل موقت کانتینرها باید روی دیسک با ظرفیت کافی باشد؛ این تنظیمات به tmpfs یک‌گیگابایتی متکی نیستند.

## ۴. Docker، Nginx و ویدیوهای قبلی

`client_max_body_size 1025m` اجازهٔ عبور فایل دقیقاً ۱ GiB همراه سربار multipart را می‌دهد. سقف واقعی خود فایل همچنان در بک‌اند ۱٬۰۷۳٬۷۴۱٬۸۲۴ بایت است. timeoutهای دریافت بدنه و ارسال/دریافت پراکسی در Nginx برابر ۳۹۰۰ ثانیه هستند. `proxy_request_buffering off` از یک کپی کامل اضافه در Nginx جلوگیری می‌کند. پراکسی Next.js و XHR نیز مهلت ۳۹۰۰ ثانیه دارند. فرمان پیش‌فرض تصویر بک‌اند و فرمان تولیدی Compose هماهنگ شده‌اند.

هیچ migration یا تغییر ساختار ذخیره‌سازی انجام نشده است. فایل‌های قدیمی بازنویسی، تبدیل یا حذف نشده‌اند. Navbar، Sidebar، CSS و طراحی کلی تغییر نکرده‌اند. داده‌های آزمون در پایگاه‌دادهٔ مستقل QA ایجاد شدند؛ حذف فایل در آزمون‌ها فقط برای رسانه‌های همان پایگاه‌دادهٔ آزمایشی انجام شد.

تغییرات در سورس و تنظیمات پروژه هستند. کانتینرهای اصلی موجود با این تغییرات بازسازی نشده‌اند؛ آزمون اجرایی با یک پشتهٔ جدا، ساخت production تازهٔ فرانت‌اند، Gunicorn، Nginx و MinIO انجام شد. هنگام استقرار باید تصاویر backend/frontend بازسازی و تنظیمات Nginx بارگذاری شوند.

## ۵. نتایج آزمون‌های انجام‌شده

آزمون واقعی HTTP از مسیر Nginx → فرانت‌اند production → Gunicorn/Django → MinIO اجرا شد. حجم فایل‌های بزرگ واقعاً روی شبکه منتقل شد؛ فقط عدد حجم mock نشده است. برای ساخت فایل آزمون، یک ویدیوی سالم کم‌وضوح H.264 تولید و یک box معتبر `free` به MP4 اضافه شد تا حجم دقیق حاصل شود. این آزمون ظرفیت انتقال و ذخیره‌سازی را می‌سنجد و معادل آزمون بار رمزگشایی یک ویدیوی واقعی 4K با بیت‌ریت بالا نیست.

| سناریو | نتیجه مشاهده‌شده |
| --- | --- |
| ۱۰۰٬۰۰۰٬۰۰۰ بایت، ۳۰ ثانیه | قبول، HTTP 201؛ بررسی کامل هش SHA-256 ذخیره‌شده و پاسخ Range با HTTP 206 |
| ۹۰۰٬۰۰۰٬۰۰۰ بایت، ۹۰ ثانیه | قبول، HTTP 201؛ بررسی کامل هش ذخیره‌شده و پاسخ Range |
| دقیقاً ۱٬۰۷۳٬۷۴۱٬۸۲۴ بایت، ۱۲۰ ثانیه | قبول، HTTP 201؛ بررسی کامل هش ذخیره‌شده و پاسخ Range |
| ۱٬۰۷۳٬۷۴۱٬۸۲۵ بایت، ۱۲۰ ثانیه | رد، HTTP 413 |
| ۱۲۱ ثانیه | رد، HTTP 422 |
| ویدیوی سالم ۰٫۱ ثانیه‌ای | قبول، HTTP 201 |
| فایل خراب | رد، HTTP 422 |
| ارسال chunked بدون Content-Length | قبول، HTTP 201 |
| لغو اتصال پس از ارسال ۴ MiB از درخواست بزرگ | بدون ایجاد رسانه؛ بررسی بعدی: صفر فایل موقت پراکسی و Django |
| بدنهٔ بزرگ‌تر از سقف Nginx با سربار | رد، HTTP 413 |
| ویدیوی صوتی بدون جریان تصویر و ویدیوی دارای فریم خراب | رد در آزمون خودکار با FFmpeg واقعی |
| ویرایش پروژه با ویدیوی قدیمیِ بدون تغییر | قبول در آزمون خودکار؛ بررسی جایگزینی، حذف صریح و دسترسی فایل نیز انجام شد |

اجرای مجموعهٔ بک‌اند: **۶۴ موفق و ۱ skipped**؛ مورد skipped مربوط به دسترسی تست به فایل ترجمهٔ فرانت‌اند در کانتینر بود و جداگانه روی میزبان **موفق** اجرا شد. پس از نهایی‌کردن تنظیمات رمزگشایی، مجموعهٔ مرتبط با این تغییر با فایل ترجمهٔ متصل‌شده دوباره اجرا شد: **۳۱ موفق، بدون skipped**.

آزمون فرانت‌اند با Vitest: **۵۱ موفق در ۱۰ فایل تست**. typecheck، ESLint و ساخت production موفق بودند. Ruff، اعتبارسنجی Compose تولیدی و `nginx -t` نیز موفق بودند.

در بررسی پایانی، لغو درخواست CSRF هم به مسیر آپلود متصل شد تا لغو قبل از شروع XHR منتظر پایان درخواست CSRF نماند. برای این تغییر یک تست Vitest افزوده شد. پس از توقف Docker، اجرای مجدد کل Vitest/typecheck/ESLint و build برای این تغییر آخر ممکن نشد؛ وابستگی‌های محلی Windows نیز برای اجرای Vitest کامل نبودند. خود سورس TypeScript این مسیر با ابزار TypeScript موجود بارگذاری و چهار بررسی مستقیم Node با موفقیت اجرا شد: لغو fetch مربوط به CSRF، شروع‌نشدن XHR پس از لغو CSRF، شروع‌نشدن هیچ درخواست برای signal ازپیش‌لغوشده، و مرز دقیق حجم/مدت. فرمت همهٔ فایل‌های فرانت‌اند تغییرکرده با Prettier و فایل‌های Python تغییرکرده با Ruff در بررسی پایانی موفق بودند. بنابراین ادعای «۵۲ تست Vitest پاس‌شده» نمی‌شود.

اسکریپت آزمون مستقیم پایانی: `.local/video-upload-qa/verify-csrf.cjs`، قابل اجرا با `node .local/video-upload-qa/verify-csrf.cjs` در همین محیط محلی. این آزمون جایگزین typecheck کامل پروژه نیست.

## ۶. محدودیت‌های آزمون و نکات باقی‌مانده

- آزمون مرورگر واقعی برای ظاهر روشن/تاریک و پخش بومی فایل ۱ GiB پس از این تغییر انجام نشده است؛ تست رابط با jsdom و تست رسانه از طریق HTTP Range انجام شده‌اند.
- TLS واقعی، دامنهٔ عمومی، پراکسی/CDN بیرونی، شبکهٔ کم‌سرعت با ارسال یک‌ساعته، بار هم‌زمان چند فایل و ویدیوی سنگین 4K/8K آزمون نشده‌اند. هر پراکسی بیرونی نیز باید سقف و timeout سازگار داشته باشد.
- لغو حین انتقال با پاک‌سازی فوری آزمون شد. اگر کاربر پس از دریافت کامل فایل توسط بک‌اند و هنگام اعتبارسنجی/ذخیره لغو کند، ممکن است پردازش بک‌اند تمام شود و یک رسانهٔ مدیریت‌شدهٔ بدون اتصال باقی بماند. پاک‌سازی موجود پروژه رسانه‌های مدیریت‌شدهٔ بدون اتصالِ قدیمی‌تر از ۲۴ ساعت را هنگام آپلود بعدی یا اجرای `python manage.py cleanup_uploads` جمع می‌کند. حذف فوری در این رقابت زمانی ادعا نمی‌شود؛ اجرای دوره‌ای فرمان برای محیط تولید لازم است.
- تکرار پایانی آزمون ۱ GiB برای نمونه‌برداری حافظه آغاز شد، اما خروجی نهایی آن و فایل اندازه‌گیری به‌دلیل قطع دسترسی Docker بعد از وقفهٔ جلسه قابل دریافت نبودند. برای سقف مصرف حافظه عدد تأییدشده‌ای اعلام نمی‌شود؛ موفقیت انتقال ۱ GiB در جدول بالا مربوط به اجرای کامل قبلی با نتیجهٔ دریافت‌شده است.
- در پایان Docker با پیام `Docker Desktop is unable to start` پاسخ می‌داد. تلاش برای بازکردن Docker Desktop مشکل موتور را برطرف نکرد. به همین دلیل حذف نهایی کانتینرهای مستقل QA قابل تأیید نیست. پس از رفع مشکل Docker، از ریشهٔ پروژه فرمان `docker compose -p ctrlz-video-qa -f .local/video-upload-qa/compose.yml down` فقط پشتهٔ آزمایشی این کار را جمع می‌کند؛ شبکهٔ خارجی و ذخیره‌سازی اصلی را حذف نمی‌کند. پاک‌سازی فایل‌ها و رکوردهای رسانهٔ اجرای کامل قبلی، پیش از این مشکل تأیید شده بود.
- حذف هیچ ویدیوی قبلی یا تغییر دادهٔ تولیدی برای اجرای این تغییر انجام نشده است.
